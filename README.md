# ИАД: задача о назначении — островной генетический алгоритм

**Статус:** учебная реализация задачи назначения. Классический ГА без кроссовера; островная модель с последовательным исполнением островов (не multiprocessing).

## Постановка

Даны `n` мест и `n` работников, матрица стоимостей `C[i][j]` назначения работника `j` на место `i`. Перестановка `vector[i]` кодирует работника, назначенного на место `i`. Каждый работник используется один раз. Минимизируется `cost = sum(C[i][vector[i]])`. Приспособленность в ГА — **`fitness = 1 / cost`**; чем она больше, тем лучше. Входной домен программы намеренно уже общего математического: каждый элемент квадратной непустой матрицы должен быть **строго положительным конечным числом**, чтобы избежать деления на ноль. Матрица с нулевым элементом отклоняется до начала поиска.

## Словесный алгоритм

1. Создать `k` независимых островов по `N` случайных допустимых перестановок. Оценить стоимость и приспособленность каждой особи. Инициализировать архив лучших найденных решений.
2. На каждом острове применить мутацию с вероятностью `p`: разрезать вектор в случайной точке `i` (от `1` до `n-1`) и поменять части местами (`vector[i:] + vector[:i]`). Это **циклический сдвиг, не инверсия**. Для `n=1` операция тождественная, новый объект всё равно создаётся.
3. Добавить мутантов к исходной популяции, обновить архив. Турнирным отбором (`t` случайно выбранных особей с возвращением → лучшая по fitness) вернуть размер до `N`. Архив сохраняет лучшую оценённую особь, даже если её случайно исключили из поколения. Кроссовера нет.
4. После завершённых поколений `10, 20, 30, ...` для `k>=2` снять снимок 10% лучших *с каждого* острова; мигрировать строго **по кольцу** `P_i → P_(i+1)%k`. На всех принимающих островах выполнить отбор до `N`. Никаких отправок «всем остальным» нет.
5. Для каждого острова отдельно отслеживать число поколений без **строгого улучшения исторически минимальной стоимости**. Плато острова — 3 поколения без улучшения (значения параметризуются).
6. Общая остановка: если `k=1`, достаточно трёх поколений стагнации. Если `k>=2`, только после хотя бы одной фактической миграции и минимум трёх новых поколений после **последней** миграции, когда все острова одновременно на плато. Независимый жёсткий лимит — максимум 1000 выполненных поколений; если лимит меньше окна первой миграции, допустимо завершение без миграций.
7. Вернуть **лучшую за всё время** особь среди архивов островов, реальную стоимость, причину остановки (`plateau_all_islands` / `max_iterations`), число поколений и число миграций.

Это утверждённая интерпретация пункта таблицы о плато (пользователь согласовал 14.10.2026), а не буквальная цитата преподавателя. В Excel одновременно встречаются словосочетания «круговой обмен» и «во все другие популяции»; реализация следует **круговому обмену** по Q3. Формулировку F3 «Сотрудник i назначается на место x_i» надо согласовать с индексами кода; P3 «мутация инверсией» неточна — на деле циклический сдвиг.

## Параметры по умолчанию

| Параметр | Значение |
|---|---:|
| Островов `num_islands` | 3 |
| Особей на остров `population_size` | 50 |
| Вероятность мутации `mutation_probability` | 0.7 |
| Размер турнира `tournament_size` | 2 |
| Обмен через `migration_interval` | 10 поколений |
| Доля мигрантов `migration_percent` | 10% |
| Плато `plateau_limit` | 3 поколения |
| Верхняя граница `max_iterations` | 1000 |

Параметры задаются через `GAConfig` либо аргументы CLI и проверяются перед запуском. `seed` задаётся отдельно для воспроизводимости. Переходы между вращательными классами перестановок мутацией **невозможны**, и это осознанное ограничение качества поиска.

## Запуск

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python lab1/lab1_test.py --matrix ideal_matrice --seed 42 --runs 30
python lab1/test_scipy.py
python benchmarks/run_experiments.py --sizes 4 5 8 16 32 64 --seeds 30
```

`ideal_matrice` — 5×5 с единицами на диагонали и 100 вне, точное оптимальное назначение `[0,1,2,3,4]`, стоимость 5. В тестовом CLI доля успехов — фактически измеренный процент запусков. Нет гарантии найти точный оптимум в каждом запуске.

`lab1/island_ga.py` — единый контроллер; `lab1/lab1.py` — особи и острова; `lab1/validation.py` — проверки; `lab1/exact_solver.py` — точный алгоритм SciPy только для сравнения; `tests/` — регрессионные тесты; `benchmarks/` — сравнение размерностей. Старый `lab1_test_migrations.py` сохранён как тонкая совместимая оболочка.

Экспериментальная статистика **не утверждается без CSV**. Исторические оценки 70%/63% из предыдущих заметок не считаются доказанными без идентичных семян, матриц и параметров. См. `benchmarks/README.md`.
