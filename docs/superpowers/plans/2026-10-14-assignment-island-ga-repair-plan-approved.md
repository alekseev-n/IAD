# Задача о назначении: план исправления островного ГА

> **Для агентов:** ОБЯЗАТЕЛЬНО используйте `superpowers:subagent-driven-development` (предпочтительно) или `superpowers:executing-plans`, выполняйте задачи по порядку. Каждая задача — TDD: RED → GREEN → регрессионные тесты → отдельный коммит. **Не изменяйте `main` напрямую.**

**Goal:** Исправить воспроизводимые ошибки островного генетического алгоритма для задачи о назначении, согласовать его поведение с третьей строкой «ИАД.xlsx», обеспечить надёжное тестирование и исследование размерностей без изменения четырёх утверждённых проектных решений.

**Architecture:** Сохранить классы `Employee`, `Employees` и последовательную островную модель. Выделить управление алгоритмом из тестового скрипта в отдельный модуль; использовать независимую историю лучших решений для каждого острова и глобальный архив. Синхронная миграция выполняется по кольцу с фиксированным интервалом; остановка проверяется по каждому острову, но не раньше контрольного окна после первой миграции.

**Tech Stack:** Python (зафиксировать и проверить поддерживаемые версии), `pytest`, стандартная библиотека, `scipy.optimize.linear_sum_assignment` **только в эталонном решателе/исследовании**, не внутри самого ГА.

**Spec:** третья строка предоставленной таблицы `ИАД.xlsx` + утверждённые ответы пользователя от 14.10.2026 (1А, 2А, 3Б, 4А). В таблице: задача о назначении, турнирный отбор, кольцевой обмен, 10% лучших, интервал 10 поколений, плато 3 поколения, предел 1000 поколений. Для противоречия слов «во все другие популяции» и «круговой обмен» окончательно выбран **обмен по кольцу**.

**Baseline:** `alekseev-n/IAD`, `main`, SHA `46998f8f6175aa94cc4da0bcdbc2e7b315dfa02e` (проверен через GitHub 14.10.2026). План не является доказательством прохождения тестов: исходные тесты необходимо запускать в рабочем окружении.

## Утверждённые решения — не обсуждать заново без новых требований

| Вопрос | Решение | Обязательный смысл |
|---|---|---|
| **1А. Мутация** | **Только существующий циклический сдвиг** | Не внедрять swap, инверсию, PMX/OX или кроссовер. На `n ≥ 2` мутация меняет части местами; для `n=1` безопасное тождественное действие. Честно описать ограниченную достижимость перестановок. |
| **2А. Остановка** | **Все острова должны находиться на плато после миграционного цикла** | Отслеживать индивидуальные островные плато, разрешить хотя бы один реальный обмен и последующие 3 поколения; только затем принимать решение об общем завершении. Максимум 1000 поколений имеет приоритет как страховка. |
| **3Б. Fitness** | **Сохранить `fitness = 1 / cost`** | Не добавлять `+1` к знаменателю. Для простоты гарантии валидировать **строго положительные, конечные элементы матрицы**: это сознательно более узкий домен, чем математически возможные матрицы с отдельными нулями. Неподходящие матрицы отклонять понятным `ValueError`, а не получать `ZeroDivisionError`. |
| **4А. Параллелизм** | **Последовательное исполнение островной модели** | НЕ внедрять `multiprocessing`, `ProcessPoolExecutor` и потоки. Называть реализацию «островная/мультипопуляционная модель», а не утверждать, что острова исполняются одновременно. |

## Точный контракт остановки для реализации (решение 2А)

1. `completed_generations` — число **полностью выполненных** шагов обычной эволюции *на каждом* острове; стартует с 0. На всех островах одна синхронная итерация.
2. После каждого поколения для острова обновлять `historical_best_cost` и `no_improvement_generations`. Улучшение — **строго меньшая** стоимость; при улучшении счётчик без улучшений обнуляется, иначе увеличивается на 1. Стоимости в выбранных тестах целочисленные; если поддерживаются дробные значения, сравнение и точность должны быть явно согласованы, но никакой произвольной константы `0.04` быть не должно.
3. Каждый остров имеет индивидуальный флаг `stalled = no_improvement_generations >= plateau_limit` (по умолчанию 3). Острова **продолжают эволюционировать** до глобальной остановки — «замораживания» нет.
4. Миграция происходит **после** 10-го, 20-го, 30-го… *завершённого* поколения, если не достигнут жёсткий лимит. Передача мигрантов — синхронный snapshot всех источников, только в следующий остров `P(i) → P((i+1) mod k)`; после добавления — отбор обратно до `N`.
5. После миграции проверить, не улучшился ли исторический лучший результат острова: если да, обновить архив и обнулить счётчик стагнации. Даже если лучшая стоимость не изменилась, глобальная остановка **не разрешена** до завершения как минимум `plateau_limit` новых поколений **после последней миграции**.
6. Для **`num_islands >= 2`** глобальная остановка по плато допустима, только если (a) уже была хотя бы одна миграция, (b) с последней миграции завершилось минимум `plateau_limit` поколений, (c) **все** острова имеют `stalled=True`. Поэтому при дефолтах самая ранняя возможная остановка по плато — после **13-го выполненного поколения** (миграция на 10-м плюс 3 новых). Для **`num_islands=1`** миграции вообще нет, и алгоритм вправе остановиться после 3 последовательных поколений без улучшения исторического минимума без ожидания несуществующего обмена.
7. Независимое защитное условие `completed_generations >= max_iterations` (1000 по умолчанию) останавливает вычисления в любом случае. Если пользователь задал `max_iterations < migration_interval + plateau_limit`, алгоритм честно завершится по лимиту без обещания миграции; отразить это в `stop_reason` и документации.
8. Результат — **лучшая исторически найденная** особь среди всех островов, а не просто победитель последнего турнира. Вернуть `stop_reason`, `completed_generations`, `migration_count`.

Контракт 2А — выбранная **проектная интерпретация** задания, а не цитата преподавателя. Его необходимо одинаково отразить в коде, словесном алгоритме и презентации. При необходимости можно отдельно согласовать точную семантику с преподавателем без самостоятельного переписывания реализации.
